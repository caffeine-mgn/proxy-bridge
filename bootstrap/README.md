# Бутстрап

Минимальная программа для **удалённой машины**. Её задача — принять по USB-COM
файл от `proxy-bridge` на Raspberry Pi и сохранить его в рабочий каталог.

Написана на Java, без единой сторонней зависимости: `javac`/`java` из JDK или JRE
достаточно. Протокол — тот же, что был в Bluetooth-бутстрапе проекта.

## Как доставить на удалённую машину

Для машин без сети файлы доставляются **«печатью» с USB-клавиатуры**: малина
представляется клавиатурой, а вы в Блокноте нажимаете «сохранить».

1. На малине включите режим фронта (`front.enabled: true` в `config.yaml`).
2. Откройте `http://<малина>:8900/`.
3. Для каждого файла нажмите «Напечатать» и сохраните в Блокноте под показанным
   именем (раскладка на удалённой машине — **US**): `Bootstrap.java`,
   `settings.txt`.
4. В `settings.txt` впишите свой COM-порт (пусто — бутстрап спросит при запуске).
5. Запустите одним из способов:

   ```bash
   # 1. Без сборки вообще (Java 11+): запуск одиночного файла
   java Bootstrap.java

   # 2. Сборка встроенными средствами JDK (без Gradle/Maven)
   ./build.sh          # Linux/macOS
   build.bat           # Windows
   java -jar bootstrap.jar

   # 3. Если Gradle на машине уже есть
   gradle build && gradle run
   ```


## Как принять программу

1. На странице фронта нажмите «Отправить себя через bootstrap» (конкретный файл
   можно задать в `front.selfPath`).
2. Бутстрап примет файл и положит его в `workdir` (по умолчанию `incoming`),
   печатая прогресс в консоль.

## Протокол

```
START_FILE  1 байт   1 = начало файла
nameLen     4 байта  длина имени, big-endian
name        nameLen  имя файла, UTF-8
size        4 байта  размер тела, big-endian
payload     size     тело
```

## Почему нет зависимостей и обязательного `build.gradle`

Бутстрап запускается на **максимально ограниченной** машине, часто без сети.
Gradle и Maven в таком окружении:

- могут быть не установлены вообще;
- даже установленные, тянут дистрибутив/плагины из сети при первом запуске.

Поэтому зависимостей нет ни одной, а основная сборка — `javac` из JDK. Файлы
`build.gradle.kts` / `settings.gradle.kts` лежат рядом как **необязательный**
вариант: они ничего не скачивают (зависимостей нет), но требуют установленного
Gradle. В списке файлов для «печати» их можно скрыть настройкой
`front.bootstrapExclude`.

## Доступ к COM-порту без библиотек

В стандартной Java нет API последовательных портов, поэтому:

- **Linux/macOS** — порт это файл устройства: настраиваем линию через `stty`
  (`raw -echo`) и читаем `FileInputStream`;
- **Windows** — читаем через встроенный PowerShell
  (`System.IO.Ports.SerialPort`), который отдаёт сырые байты в свой stdout,
  а Java читает этот поток.

Для Linux/macOS ничего дополнительно не нужно; для Windows — только PowerShell,
который есть в системе.

## Ограничения

- Имя файла и содержимое не шифруются: это локальный USB-кабель, а не сеть.
- Контроль целостности — по размеру; при обрыве связи бутстрап сообщит ошибку и
  продолжит ждать следующий файл.
